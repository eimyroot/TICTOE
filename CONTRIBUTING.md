# Contributing

Thanks for contributing to TICTOE.

## Before you start

- Open an issue for substantial behavior changes or architectural work.
- Keep changes narrowly scoped and avoid unrelated refactors.
- Never commit credentials, secrets, production data, or personal data.

## Development

Use the Node.js version and commands documented in the repository. Install dependencies from the lockfile, run the available checks, and verify the affected behavior locally before opening a pull request.

## Pull requests

A pull request should explain what changed, why it changed, how it was tested, and any compatibility or security impact. Keep generated files and unrelated formatting churn out of the diff.

By contributing, you agree that your contribution is submitted under the repository's existing license and project terms.
